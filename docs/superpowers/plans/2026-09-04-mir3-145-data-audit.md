# 《传奇3》1.45 数据核对清单 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 从本服正式 `Database/System.db` 完整导出物品、怪物和套装，依据可复核资料建立光通《传奇3》1.45 基准清单，并生成逐条 Markdown 对比报告。

**Architecture:** 使用只读 .NET 反射导出器调用现有 `Library.dll`/MirDB 读取正式系统库，避免自行猜测加密格式；使用 Python 标准库完成名称归一化、别名匹配、覆盖率校验和 Markdown 生成。官方基准与本服快照分别保存为 JSON，最终报告引用来源并将结论限制为“保留、同物异名、版本不确定、建议删除候选”。

**Tech Stack:** .NET 8 控制台程序、现有 .NET Standard `Library.dll`、Python 3 标准库、JSON、Markdown、Git。

---

## 文件结构

- `tools/mir3-data-audit/Mir3DataAudit.csproj`：只读数据库导出器工程定义，只引用仓库已有 `Library.dll`。
- `tools/mir3-data-audit/Program.cs`：加载 MirDB，导出物品、怪物、套装和数据库 SHA-256；不调用任何保存接口。
- `tools/mir3-data-audit/compare.py`：读取本服快照和官方基准，归一化名称、判定匹配状态并生成 Markdown。
- `tools/mir3-data-audit/tests/test_compare.py`：覆盖名称归一化、别名匹配、未知项和报告完整性。
- `tools/mir3-data-audit/verify_snapshot.py`：校验数据库未被修改、快照集合完整、基准引用有效和报告覆盖完整。
- `audit/mir3-145/current-system.json`：从正式 `System.db` 生成的本服快照，不包含用户库数据。
- `audit/mir3-145/official-reference.json`：1.45 官方基准、别名和逐项证据。
- `docs/research/mir3-145-sources.md`：检索范围、来源等级、版本边界和资料缺口。
- `docs/audits/mir3-145-data-comparison.md`：交付给用户核对的完整对比表。

### Task 1: 建立只读 MirDB 导出器

**Files:**
- Create: `tools/mir3-data-audit/Mir3DataAudit.csproj`
- Create: `tools/mir3-data-audit/Program.cs`

- [ ] **Step 1: 先写快照验证器并确认当前没有可验证输出**

`verify_snapshot.py` 接受 `--snapshot`、`--database` 和 `--expected-sha256`，检查 JSON 顶层包含 `database`、`items`、`monsters`、`sets`，三类集合非空、每类索引唯一，并验证 JSON 散列、实际 `System.db` 散列和命令行期望散列完全一致。失败时退出码为 1 并输出具体字段。

Run:

```bash
python3 tools/mir3-data-audit/verify_snapshot.py \
  --snapshot audit/mir3-145/current-system.json \
  --database Database/System.db \
  --expected-sha256 "$(shasum -a 256 Database/System.db | awk '{print $1}')"
```

Expected: FAIL，原因是导出器和快照尚不存在。

- [ ] **Step 2: 创建最小 .NET 工程**

`Mir3DataAudit.csproj` 使用 `net8.0`、`ImplicitUsings=enable`、`Nullable=enable`，通过 `<Reference Include="Library"><HintPath>../../Library.dll</HintPath><Private>false</Private></Reference>` 引用现有程序集，不引入 NuGet 包。

- [ ] **Step 3: 实现程序集解析和只读会话加载**

`Program.cs` 接受 `export --database <absolute System.db> --output <json>`，注册 `AssemblyLoadContext.Default.Resolving` 并只从仓库根目录加载依赖。程序创建临时目录，仅复制 `System.db`，不复制 `Users.db`；反射加载 `Library.dll`，创建 `MirDB.SessionMode.Server` 会话并调用 `Init()`。代码中禁止调用 `Save`、`Commit` 或 `SaveSystem`。

- [ ] **Step 4: 导出稳定 JSON**

输出按数据库索引排序：

```json
{
  "database": {"path": "Database/System.db", "sha256": "64位小写十六进制散列", "exportedAt": "2026-09-04T12:00:00Z"},
  "items": [{"index": 1, "name": "木剑", "itemType": "Weapon", "requiredClass": "All", "requiredAmount": 0, "image": 1}],
  "monsters": [{"index": 1, "name": "鸡", "level": 1, "ai": 1, "image": "Chicken", "isBoss": false}],
  "sets": [{"index": 1, "name": "示例套装", "groups": [{"name": "首饰组", "requiredNumItems": 2, "items": ["示例戒指", "示例手镯"]}]}]
}
```

所有必需反射字段缺失时必须终止并报错，不能静默生成空集合；临时目录在 `finally` 中删除。

- [ ] **Step 5: 运行导出并验证数据库没有变化**

